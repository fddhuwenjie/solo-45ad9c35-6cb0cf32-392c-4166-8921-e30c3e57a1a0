# 舞台快速换装编排

Flask（规则计算/排程）+ SQLite（演出与修订）+ 原生 JavaScript/SVG（场次时间轴、侧台平面图、服装层级卡联动）。

## 运行

```bash
python3 seed.py        # 首次：写入演示数据（含刻意安排的冲突）
python3 app.py         # 依赖 Flask（本环境装在 ../.pylibs，app.py 已自动加入 sys.path）
# 打开 http://127.0.0.1:5000
```

## 功能

- **录入**：演员出入口、角色造型（look↔服装清单）、穿脱依赖（层级顺序）、单件用时、
  服装师、换装位（坐标/容量）、服装车（停靠侧/容量）、场景间隔（场次起止）。
- **时间轴**：拖动任务块调整开始时间；点击选中；已锁节点（连排确认）不可拖动、重排不动。
- **重排规则**：动作先后（脱外→脱内→穿内→穿外→取道具）、人员并发（演员/服装师独占）、
  步行时间（平面图坐标/1.3m/s）、换装位容量、服装复用（copies 与脱下时刻）、
  清洁/维修状态（available_at 前不可用）。
- **冲突报告**：最早无法按时完成的动作（含预计/截止时刻）、服装师并发、换装位容量、
  缺件/复用冲突；并给出改动较少的替代排法（换装位/服装师/开始时间），可一键采用。
- **变更联动**：改场次时间或服装状态/服装车 → 仅关联任务置「待复核」，可逐个销记。
- **修订**：任意时刻存档快照，可恢复。
- **连排实测回放**：从指定修订开启连排（基准计划冻结在连排快照中，实测不改写基准方案，
  回看时计划条只读该连排冻结 plan，与实测同轴叠放，不受当前方案漂移影响）；
  按动作打点开始/完成/跳过/异常，异常与补正必须留理由，补正保留原记录；
  穿/脱打点可登记现场实际使用的服装与副本编号，据此识别错用服装、副本编号无效、
  同一副本重叠占用；同一时间轴叠放计划与实测，联动演员/服装师/换装位/服装副本占用，
  检查时刻倒序、动作漏项、并发冲突、错用服装，并定位首个偏差及后续等待链；
  连排结束后按服装动作×完整人员配置（具体服装师/自助）汇总多次实测（P75）给出时长建议；
  勾选建议后从所选连排的基准修订派生新修订——只重排受影响任务，锁定节点不动，
  不触碰当前可变方案。
- **导出**：个人换装提示单（HTML 打印）、服装流转表（CSV）、带冲突标记的 SVG 时间线、
  计划—实测叠放 SVG、带异常理由的连排记录（HTML）。

## 主要接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/state` | 全量状态 + 排程结果 + 连排列表 |
| POST | `/api/reschedule` | 重排（已锁不动）并返回替代排法 |
| POST | `/api/tasks/<id>` | 拖动/改派/锁定/解锁 |
| POST | `/api/scenes/<id>`、`/api/items/<id>` | 变更并标记关联任务待复核 |
| POST | `/api/revisions`、`/api/revisions/<id>/restore` | 修订存档/恢复 |
| POST | `/api/runs` | 从指定修订开启连排（冻结基准计划快照） |
| POST | `/api/runs/<id>/events` | 动作打点（开始/完成/跳过/异常；异常与补正须留理由；可带现场 item_id/copy_id） |
| POST | `/api/runs/<id>/close` | 结束连排（之后只读） |
| GET | `/api/runs/<id>` | 连排详情：冻结基准计划、事件、实测检查与等待链 |
| GET | `/api/runs/summary?revision_id=` | 按基准修订汇总连排 → 时长建议（服装动作×服装师分组） |
| POST | `/api/runs/derive` | `{run_id, keys}` 从所选连排的基准修订派生新修订（不触碰当前方案） |
| GET | `/export/cue/<actor_id>`、`/export/flow.csv`、`/export/timeline.svg` | 三类计划导出 |
| GET | `/export/run/<id>/compare.svg`、`/export/run/<id>/record` | 计划—实测 SVG、连排记录 |
